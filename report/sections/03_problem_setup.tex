\section{Problem Setup}
\label{sec:problem-setup}

We study low-latency \task on \dataset \cite{lei2020tvr} in two related evaluation settings. The lightweight subtitle-window baselines in this repository use a clip-conditioned setup: each query is paired with a video clip $\video$ identified by \texttt{vid\_name}, together with aligned subtitle text and a gold temporal span $(t^{*}_{st}, t^{*}_{ed})$. In that setting, the task is to predict the start and end timestamps $(\hat{t}_{st}, \hat{t}_{ed})$ of the matching moment within the given clip. The \xml experiments use the official TVR corpus-level protocol, where the model must retrieve the relevant video and localize the moment. The strongest result in this report is therefore a VCMR result, not a claim of improved SVMR.

\paragraph{Search space.}
We use two search granularities. In the subtitle baselines, each known clip is represented as an ordered sequence of overlapping subtitle windows $\window_k = [a_k, b_k]$ with associated text. A text-only method ranks those windows and returns the best temporal span directly. For the corpus-level \xml runs, dense retrieval is used at the video-routing level: it produces a small set of candidate videos for each query, and \xml then performs cross-modal scoring and localization on that retained set. Separately, the shared-compaction ablation prunes the temporal feature sequence inside \xml, but that is not the main dense-to-\xml result.

\paragraph{Fixed-feature setting.}
Our work operates in the feature regime provided by \dataset and the official \xml implementation. Video and subtitle features required by \xml are prepared offline, and subtitle-window construction is also treated as preprocessing. As a result, the measured validation cost is dominated by query-time retrieval, candidate selection, and multimodal scoring. This setup is important because the project does not attempt to reduce feature-extraction cost from raw video; it asks how much validation wall-clock time can be saved after the features already exist.

\paragraph{Objective.}
The practical objective is to preserve the quality of cross-modal localization while reducing fixed-feature validation runtime. Text retrieval methods such as \bm, dense sentence-transformer retrieval, and their fusion are evaluated first as inexpensive subtitle-search baselines. The main systems question is sharper: can a cheap dense retriever route each query to a much smaller candidate set before \xml runs, improving VCMR validation runtime without sacrificing the localization behavior that makes \xml useful?

\paragraph{Evaluation target.}
We measure localization with intersection-over-union (IoU) between the predicted span and the gold span. For the subtitle-window baselines, the implementation reports recall at top-$1$ and top-$3$ under IoU thresholds of $0.3$ and $0.5$, along with mean IoU and absolute start and end errors for the top prediction. For official \xml runs, we use the TVR standalone metrics: VR for retrieving the correct video, SVMR for localizing within a known video, and VCMR for retrieving both the video and moment from the corpus. Runtime is reported in milliseconds per query. We do not use query-type-specific validation breakdowns in this report.
